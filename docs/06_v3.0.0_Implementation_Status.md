# Master Design vs Reality — v3.0.0 Implementation Status

> Companion to [`01_WMS_Master_Design.md`](./01_WMS_Master_Design.md).
> Master design = stable vision; this doc = where we actually are as of `v2.15.0-beta-ready` (Day 17, 2026-05-17).

Updated per phase. Re-read before sales conversations + before v3.1+ planning.

---

## TL;DR

We've shipped **roughly 90% of Master Design's Phase 1** (B2B operational core) and added **7 v3.0.0 chapters** the design didn't anticipate (Reports / Tenant Admin / Security Hardening / Deployment / Onboarding / Documentation / Polish).

We've shipped **~14% of Phase 2** (pack video only) and **0% of Phase 3** (3PL billing). Phase 4 = correctly deferred per design.

**5 honest red flags** could surface in sales conversations or first-customer operations. Two are showstoppers if the first customer is a 3PL: no billing module, no activity logging for billable hooks. The others are operational deviations from the design's ambition.

## 5. 🚨 Red Flags

Honest gaps between design ambition and shipped reality. Surface these proactively in sales conversations; the alternative is the customer discovering them post-contract.

### Red Flag 1 — SignalR is in the tech stack but never used

Design says "Real-time: SignalR (with Redis backplane for scale)". Pick task progress / live operations / 3D Monitor were all expected to use it. **Zero SignalR code in the codebase.** If marketing implies "real-time updates", we're misrepresenting.

**Action**: don't claim real-time UI updates in sales. Refresh-on-action is the truth.

### Red Flag 2 — Wave engine completely absent

Design devotes substantial space to wave generation: B2B discrete vs B2C batch (30 orders/wave), container-based (Pallet/Box-L/M/S/Tote), pick-path strategy (Sort/Snake/TSP), time + trigger generation via Hangfire, express priority queue.

We have: direct allocation → pick task per SO. No batching, no pick-path optimization, no waves.

**Impact**: at 5K orders/day, picker walk distance is the bottleneck. First B2C customer at scale will hit this within weeks.

**Action**: position v3.0.0 launch volume as "1,000-2,000 orders/day per warehouse"; wave engine is on the roadmap.

### Red Flag 3 — 3PL Billing entirely absent

Design has the largest section on this: 6 categories of activities, rate cards, aging brackets, grace period, pricing determinants, dual-mode (Direct invoice / Push to ERP), customer self-service portal, dispute workflow with credit notes. **80 functions in the catalogue.**

We have: zero. No `billing` schema. No `BillableActivities` table. No invoice generation. No rate-card UI.

**Impact**: if first customer is 3PL → blocker. If first customer is direct retailer/B2B → not a blocker but the "future SaaS multi-tenant" pitch hinges on billing.

**Action**: do NOT sell to a 3PL prospect at v3.0.0. Position for direct customers (B2B with own warehouse). Document billing as v3.1 roadmap target.

### Red Flag 4 — Strategic Allocation = FIFO only

Design specifies Push/Pull/JIT/Hybrid configurable per product/customer/category/channel, with resolution hierarchy (Product > Customer > Category > Channel > Default). Plus ATP timeline, Item Stratification multi-axis, Customer Tier (Tier1-4 with allocation priority), shelf-life-aware allocation.

We have: FIFO strategy + a resolver shell that only knows about FIFO.

**Impact**: enterprise customer asks "during stock-out, can we prioritize Tier-1 customers over Tier-3?" → no. Asks "what's our ATP for next quarter's promo?" → no.

**Action**: position v3.0.0 as "single-strategy allocation; multi-strategy + tier-aware = v3.1+". Don't promise customer-tier prioritization in v3.0.0.

### Red Flag 5 — Picker 4-tier scan vs single-page-per-task

Design vision: scanner-driven Location → Pallet → SKU → Lot validation with 8-step UI, vibration feedback on each scan, sequential validation refusing to advance until each step matches.

Shipped vision: single-page-per-task with all lines stacked, manual qty entry per line, optional location/lot/pallet inputs visible.

**Impact**: operator experience is materially different. Trained-on-design pickers will find the UI looser than expected. Untrained-on-design pickers will find the UI faster.

**Action**: this is the "right" trade-off for v3.0.0 (mobile pickers shipped 1.8× faster than spec estimate per Phase 22 retro). But don't show design mockups in sales — show the actual UI.

### Honourable mention — design's "Notification system" missing

Design Self-Review Concern #10 — unified notifications across modules. We have nothing. Customer admin can't subscribe to "low stock alert" or "PO received". TempData banners are in-page only.

**Action**: TD post-v3.0.0. Honest in sales.

## 7. Recommended v3.0.0 Launch Scope (Honest)

Based on this analysis, what we can credibly sell at v3.0.0:

### ✅ Sellable today

- Single-warehouse B2B / direct-customer WMS
- Up to ~1,000-2,000 orders/day per warehouse
- Self-managed inventory (not 3PL on behalf of others)
- Customers with simple FIFO allocation needs
- Mobile-first execution (Pick / Receive / Pack / Putaway / Count / Locate)
- Per-customer / per-warehouse user + role admin
- Comprehensive audit log (PDPA-friendly enough)
- Production deployment on Windows Server + IIS
- Sales-led onboarding (SuperAdmin tenant provisioning)

### ⚠️ Sellable with disclaimer

- B2C operations (no Returns / RMA — design intent gap for B2C launch)
- High-volume operations (no wave engine; picker walk costs accumulate)
- Multi-warehouse (Transfer ships, but no inter-warehouse allocation strategy)

### ❌ NOT sellable today

- 3PL business model (no billing module = no revenue capture)
- Marketplace integration (Shopee / Lazada / TikTok not connected)
- Enterprise allocation (Customer Tier / Push-Pull-JIT / ATP all absent)
- Real-time visibility / live ops dashboard (SignalR not used)
- Customer self-service billing portal (no billing)
- Pallet build / B2B BOL workflow
- Demand forecasting
- Supplier portal / VMI workflows

### Pre-v3.0.0 honest pitch

> "Mid-market direct-warehouse WMS. Mobile-first for staff, comprehensive admin + audit. Deployed to your infrastructure. Currently single-strategy allocation (FIFO), single-tenant per database for hard isolation. Up to a few thousand orders/day per warehouse — wave engine + advanced allocation are v3.1 roadmap. NOT a 3PL solution yet — billing module is post-launch."

That fits ~5 sentences. Avoids overpromising.
